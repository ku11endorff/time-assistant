time-assistant setup guide

Replicate your approved Kleer week (time, expenses, receipts, allowances) into TimeKeeper. Pick your route, tick off the steps, and build your config.json here.

Private by design. This page works offline and sends nothing anywhere. It never asks for a password: your TimeKeeper login goes into your keychain or the cloud environment's network secret, never into a file or this form. Ticked steps and the form are saved only in this browser (use Clear saved progress to remove them).

How do you want to work?

Not sure how it works yet? Read how-it-works.md first (five minutes).

    Build your config.json

    Fill in the ids you collected (see Where to find ids). The result follows config.example.json and is checked the same way as python3 sync.py check-config. Save it as config.json next to sync.py; it is git-ignored. Never put a password in it.

    Source and target
    Lowercase letters, digits, - or _. Also names the keychain entry time-assistant:<name>.
    Not a secret. Not needed in a cloud session.
    The client-project id of your time entries. Comma separated.
    The different ids your expenses are re-invoiced to. Add only ids you confirmed are the same project.

    First column of the project list, not the project number.
    Activities (time_map)

    One row per Kleer activity you use. Leave the Kleer id empty for a default row that takes every other activity (only one).

    Expenses (expense_map)
    The wage code named Kvitto (or yours).
    An active category. Some accounts reject receipts without one.
    Daily allowances, traktamente (allowance_map)
    Source wording (optional)
    Shown in the "week not approved" error.

    Where to find your Kleer ids
    
      
    With the Kleer connector, ask your agent: "Read my time entries and expenses for last week and list the project ids, activity ids and expense types."
    
      
    
        
    You needWhere in Kleer's dataGoes into
    
        
          
    Client-project id of your projectclient-project.id on a time entry (listEvents)source_project_ids
    
          
    Expense project id (a different id)re_invoice_project.id on an expense entry (get_expense); a new one may appear per expensesource_project_ids, in addition, once confirmed to be the same project
    
          
    Activity idactivity.id on a time entrytime_map[].source_activity_id
    
          
    Expense type namesexpense_type.name on an expense entryexpense_map keys (or just default)
    
        
    
      
    Two project ids? In Kleer a time entry carries the client-project id, an expense is re-invoiced to a dimension project with another id. If an expense shows as "not replicated", its id is missing from source_project_ids.

    Every week
    
      
    
      
      
      
      Your week is replicated only once every time entry is approved in Kleer. If one is open, the agent stops and writes nothing: approve it and ask again.
